Ground Up: Sports AI Career Assistant

An AI-powered athlete talent discovery and opportunity recommendation system. Project Milestone M2 report.

Team: Parikshit Dagar, Mehul Jakhmola
Guide: Dr Mala Saraswat
Stage: Frontend complete. Backend and AI modules are the next milestone.

1. Introduction and problem statement

Young athletes, especially outside big academies and metro cities, struggle to find trials, scholarships, tournaments and scouts that actually fit them. Opportunities are scattered across social media, local networks and word of mouth, and a search by sport or city returns long lists that ignore position, skills, age eligibility and level. Organisations posting opportunities face the mirror problem: many applications that do not meet their requirements.

Ground Up is a sports network connecting athletes, coaches, scouts and teams. Its AI component is a recommendation system: given a structured athlete profile and a pool of opportunities, it produces a ranked, explainable list of the opportunities the athlete is most compatible with.

The system measures how well a profile matches the stated requirements of an opportunity. It does not claim to measure an athlete's true potential.

Related techniques. Job recommender systems (Al-Otaibi and Ykhlef, 2012) are the closest analogue: athlete = candidate, opportunity = job posting. Content-based recommendation (Lops et al., 2011) compares feature vectors and works without interaction history. Hybrid recommenders (Burke, 2002) combine methods to offset individual weaknesses. Sports analytics research (e.g. Decroos et al., 2019) values player performance but does not match athletes to opportunities.

Whether this beats plain filtering is a hypothesis to be tested in evaluation, not an assumption.

Feasibility

  • Technical: feature encoding, TF-IDF, cosine similarity and sentence embeddings are available in standard Python libraries (pandas, scikit-learn, sentence-transformers) and run on a laptop CPU for a few thousand records. The frontend is already built.
  • Data: public player datasets give athlete attributes. Structured opportunity postings are not publicly available in bulk, so they will be generated synthetically from documented rules. There is no real compatibility ground truth, so evaluation uses a rule-based relevance definition plus a small human-rated sample. Results will be stated as prototype results on synthetic opportunities.
  • Economic: open-source software and free datasets. No paid APIs or special hardware.
  • Operational: the recommender can run as a Python function or small REST service (FastAPI/Flask) called by the Ground Up frontend with a profile and returning a ranked JSON list.

3. Objectives and methodology

Objectives

  1. Define structured representations of athlete profiles and opportunity requirements (sport, position, age, location, skills, level, goals).
  2. Build a preprocessing and feature pipeline that converts both into numerical vectors.
  3. Implement a hybrid content-based matcher that gives each eligible athlete-opportunity pair a compatibility score from 0 to 100.
  4. Rank opportunities and explain the main factors behind each score.
  5. Evaluate with Precision@K, Recall@K and NDCG@K against a filter-only baseline.
  6. Build the platform around this: verified onboarding, profiles, feed and opportunities (frontend done).

System pipeline

flowchart TD
A[Athlete profile from onboarding] --> B[Preprocessing: clean, standardise positions and skills, scale]
B --> C[Feature extraction: categories, skill vectors, TF-IDF or embeddings]
C --> D[Hard eligibility filter: sport and age range]
D --> E[Component scores and weighted compatibility score 0 to 100]
E --> F[Ranking: top K opportunities]
F --> G[Explanation: factors behind each score]
G --> H[Shown in the Ground Up feed and opportunities panel]

Matching method

Opportunities that fail hard rules (different sport, outside the age range) are removed first. The rest are scored:

Score = 100 x [ 0.25 Position + 0.30 Skills + 0.15 Age + 0.10 Location + 0.10 Experience + 0.10 Goals/Text ]

Skills and text use cosine similarity. Position uses exact match plus a small related-position table. Location is graded (same city, same region, other). The weights are initial design choices, to be tested by ablation and not presented as learned values.

Data strategy

  • Athletes: public player dataset (e.g. football attributes), licence to be checked. Ratings are a proxy for skills.
  • Opportunities: synthetic, from a rule-based generator with a fixed random seed. Real and synthetic data are kept in separate, labelled files.
  • Relevance labels: rule-based definition different from the scoring formula, plus a small human-rated sample, to reduce circular evaluation.

4. Relevance of algorithms and techniques

The problem is matching and ranking with no interaction history and no labelled ground truth, so techniques were chosen for that fit. All are planned, none implemented yet.

TechniqueRoleWhy it fits
Content-based recommendationCore framework: compare athlete and opportunity featuresWorks without interaction history, so no cold-start problem on a new platform.
Rule-based hard filtersRemove ineligible opportunities (sport, age)Eligibility is a constraint, not a preference.
TF-IDF and cosine similarityCompare skill vectors and short textFast, interpretable, unaffected by vector length.
Sentence embeddings (Sentence-BERT)Compare free-text goals and descriptionsCaptures synonyms such as "playmaker" and "creative midfielder" that TF-IDF misses. Used on text fields only.
Weighted linear scoringCombine component scores into oneTransparent and explainable. Weights can be inspected and ablated.
Random Forest / Gradient BoostingOptional re-ranking to learn weightsOnly if enough labels exist. With purely synthetic labels it may learn the labelling rule, so it is a secondary experiment.

Deliberately not used: collaborative filtering (needs interaction data the platform does not have yet, listed as future work) and deep neural recommenders (not justified by data size or labels). KNN adds nothing beyond cosine ranking.

Evaluation plan

NDCG@K is the main metric because relevance is graded and order matters, with Precision@K and Recall@K as complements. The method is compared with a filter-only baseline and a random baseline, with ablation (removing one feature group at a time) and a small human-rated sample. Results will be reported only after they are obtained.

7. Limitations

  • Opportunity data is synthetic, so results reflect the method, not real-world performance.
  • No real ground truth. Rule-based labels risk circular evaluation, reduced by using a different rule set and human judgement.
  • Public skill ratings are proxies and may not represent grassroots athletes. Data is richest for football.
  • Weights are design choices until tested. Profile data is self-reported. Using age and location may disadvantage some groups, which needs monitoring.

8. Conclusion

The Ground Up frontend is complete and shows the onboarding flow and the main feed, with clear places for each AI output. The AI core is an explainable hybrid content-based recommender that ranks opportunities for an athlete using rule-based eligibility, cosine similarity with TF-IDF and embeddings, and a transparent weighted score. The next milestone is building the data pipeline, matching engine and evaluation, then connecting them to the interface.
